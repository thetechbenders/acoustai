## GitHub rename runbook

### Before the authorized rename

1. Review and authorize the draft merge and live rename separately. At audit time, the authenticated lookup for `thetechbenders/acoustai` returned HTTP 404 and the slug was absent from the organization repository list. Recheck availability with an organization admin immediately before renaming. The rename form is the definitive availability check.
2. Record the repository ID (`1450691200` at audit), default branch, current main SHA, issues, PRs, milestones, settings and social preview. GitHub reports a public repo with Pages disabled, an empty homepage field and a custom Open Graph image. The existing description is slug-neutral and preserves the tagline verbatim. Keep the description and six topics (`3d-printing`, `acoustic-monitoring`, `edge-ai`, `esp32-s3`, `fault-detection`, `tinyml`).
3. Check installed apps and external references with their owners. Repository webhook and Actions workflow lists were empty. Organization installations include the Codex connector and Claude. Per-repository authorization and off-repository jobs or private references need owner verification. GitHub code search for the old repository path and direct checks of the Techbenders organization profile and audit document surfaced no matching external code references. Review bookmarks, external docs, Drive/HQ links, badges outside this repo, submodules, bots, CI references, and any URL or slug filters. GitHub redirects Git operations but does not redirect calls to actions hosted by a renamed repository. [GitHub rename behavior](https://docs.github.com/en/repositories/creating-and-managing-repositories/renaming-a-repository)

### Rename and verify

1. As an organization owner or repository admin, open the current repository's **Settings → General → Repository name**, enter `acoustai`, and click **Rename**. Rename the same repository in place. Reserve the old slug by leaving it unused so GitHub's redirects persist.
2. Confirm the canonical URL and repository ID, visibility and permissions, default branch and expected commit history, milestones and topics, and continuity of #10, #11, #12 and the migration PR. Check the old repository and issue/PR URLs redirect to their new equivalents.
3. Update each clone's `origin` to `git@github.com:thetechbenders/acoustai.git` or `https://github.com/thetechbenders/acoustai.git` with `git remote set-url origin <new-url>`. Check separate push URLs if configured. Run `git remote -v`, `git fetch origin` and `git ls-remote origin refs/heads/main`.
4. Update the live links in the README and this record, then verify them and the README's badge, local asset and documentation links. Update confirmed external consumers and check the installed apps can still access the renamed repository. Verify the approved social preview when it is available and update #12 with results. Owner approval governs artwork installation and the start of M1.
